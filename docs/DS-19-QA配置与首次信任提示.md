# DS-19 QA 配置与首次信任提示

日期：2026-11-07。对应 `qa/buglist-20261106.md` 的 2、3、4、5 项。

## 证据与边界

- 本机 QA 留存的 `settings-pre-p3.json` 只有 `osc52`，缺少必填的 `schemaVersion`。加载器会拒绝该文件，恢复备份或采用默认值；默认 OSC 52 读写全关。该文件是 P3 开始前的快照，不能据此断言每次 P2 测试的配置相同，P2 仍需按有效配置复测。
- shell 没有显示 `SettingsLoadResult` 的失败或备份恢复信息，用户无法得知手写设置未生效。这是本轮修复的配置反馈缺陷；不放宽配置格式，也不自动开启剪贴板权限。
- Direct 未知主机错误仍要求使用兼容模式，而有主机密钥信息时已经能提供「核对指纹…」。文案应与实际能力一致。
- 会话树连接明确设计为新建标签。保留已退出标签会保留屏幕、渲染器等资源，不能将该操作等同于同窗格重连测试，不改变多标签行为。

## 决策

1. 在 settings 层提供可单测的加载提示函数。正常加载和文件不存在不提示；损坏、备份恢复、新版本格式明确说明当前行为并附原因。
2. shell 启动时将提示加入状态栏并输出调试日志。缺失 `schemaVersion` 给出直接可操作的原因，原文件保持只读保护。
3. 未知主机携带可确认的密钥信息时，引导点击「核对指纹…」并向管理员核对；没有该信息时说明无法在此确认，保留兼容模式路径。已变更密钥的拒绝行为不变。
4. 手测前检查诊断包中的设置加载状态和有效权限；重连测试须保持标签数不变且 attempt 递增，新增/关闭标签另测。

## 验证

- 配置回归：复现缺版本但包含 OSC 52 开关的文件，验证拒绝、权限默认关闭、提示及原因；有效最小配置读写开启；备份恢复和新版本格式的提示。
- Direct 错误映射：有/无主机密钥信息时的不同文案，以及 changed 不携带信任提议。
- Windows 实机仍需复测剪贴板写、Direct 读确认和同窗格重连资源；代码与单测不能替代这些验收。
