# DS-13 按连接选择 SSH 传输

日期：2026-11-04
基线：main `6db9448`
出处：`REVIEW-增补-2026-11-02.md` D-5（「开关是全进程的环境变量，产品化前需要在 DS-2 里改成按连接选择」）；ADR-003 §决策 1；HANDOFF §4.5；`docs/TODO.md` §2.1。

凡写「决定」的地方，是本文替原设计补的选择。

## 0. 现状

- SSH 与 Hyper-V 内层 SSH 的传输由 `Win32PaneBackend::sshDirect_` 决定，它在窗格构造时读一次环境变量 `ITERM2WIN_SSH_DIRECT`（值恰好为 `1` 才算开），整个进程所有连接一样。
- `makeSshFactory(direct, &err)` → `selectSshTransport(wantDirect, buildHasDirect)`：不要 Direct → ConPTY 里的 `ssh.exe`（兼容模式）；要 Direct 且构建含 Direct → `DirectSshTransport`；要 Direct 但构建不含 → 明确失败，不回落（ADR-003 §决策 1）。
- Direct v0 只支持 agent 认证；KeyFile / Interactive 在 Direct 启动前由 `validateDirectAuthMode` 拒绝，报错文字让用户「去掉 ITERM2WIN_SSH_DIRECT」。
- 首次信任界面（DS-12）已在 main。

## 1. 目标与边界

做：

1. connections.json 每个 SSH 连接（含 Hyper-V）可以写明传输：兼容或直连。
2. 环境变量降级为**没写明传输的连接**的全局默认；写明的以连接为准。
3. 静态可判定的冲突（直连 + 非 agent 认证、未知的传输值）在加载校验时拦下，和其他字段错误一样阻止启动。
4. 报错文字指向连接字段，而不是只说环境变量。

不做：

- **不改默认值。** 没写传输、也没设环境变量的连接仍走兼容模式。是否把默认改成直连，等 Windows 手测后单独决定（HANDOFF §4.5）。
- 不加 settings.json 里的全局默认（改默认时一起决定放在哪）。
- 不做界面上的传输选择（等 D1 连接编辑器）。
- 不做失败后自动回落到另一种传输（ADR-003）。
- 本地连接不受影响（始终 ConPTY）。

## 2. schema（connections.json）

```json
"ssh": {
  "user": "gavin",
  "configSource": "managed",
  "auth": { "mode": "agent", "identityFile": null },
  "transport": "direct",
  "connectTimeoutSeconds": 15
}
```

- `ssh.transport`：可选。`"compatible"`（ConPTY + `ssh.exe`）或 `"direct"`（进程内 libssh2）。
- **省略** = 跟随全局默认（§3）。保存时**不新增**这个字段（与现有文件保持一致；写明了才写回）。
- 其他字符串（含大小写不同，如 `"Direct"`）或非字符串（数字、null、对象等）：校验报 `ssh.transport`「传输只能是 compatible 或 direct」，阻止该连接启动。不让整个文件变成 Corrupt（A5 的原则：单个连接的问题只影响这个连接）。
- 与其他非法字段一样，含非法 `transport` 的连接会让 `saveConnections` 拒绝保存（现有规则，`local.closePolicy` 也是如此），所以不需要为写回非法原值做特殊处理。
- `schemaVersion` 不变：新增的是可选字段，旧版本读到会忽略。

uicfg 模型（`ui/include/uicfg/model.h`）：

```cpp
enum class SshTransport { Compatible, Direct };
struct SshSettings {
  …
  // ssh.transport 原文：nullopt = 字段缺省（跟随全局默认）。非字符串时存其 JSON 文本（必然非法）。
  std::optional<std::string> transport;
};
// "compatible" / "direct" → 枚举；缺省、未知或非字符串 → nullopt（调用前应已通过校验）
std::optional<SshTransport> parseSshTransport(const SshSettings&);
```

## 3. 选择规则（决定）

| 连接的 `ssh.transport` | 环境变量 `ITERM2WIN_SSH_DIRECT` | 结果 |
|---|---|---|
| `"compatible"` | 任意 | 兼容 |
| `"direct"` | 任意 | 直连 |
| 省略 | `1` | 直连 |
| 省略 | 未设或其他值 | 兼容 |

选中直连而构建不含 Direct（`IT2W_SSH_DIRECT=OFF`）：窗格 Failed，不回落。

纯函数（`app/pane_backend/pane_logic.*`）：

```cpp
// perConnection：连接写明的传输；nullopt 用 envDefault（ITERM2WIN_SSH_DIRECT=1）
bool wantDirectSsh(std::optional<it2w::SshTransportMode> perConnection, bool envDefault);
```

`selectSshTransport` 不变，只改 `Unavailable` 的报错文字（§5）。

## 4. 数据流

```
connections.json ssh.transport
   → uicfg::validate（未知值 / 直连+非 agent → 阻止启动）
   → uicfg::describeLaunch：SshLaunchDesc.transport（std::optional<SshTransport>）
     （HyperVLaunchDesc.ssh 同样带上）
   → main.cpp sshOptions()：it2w::SshLaunchOptions.transport
   → Win32PaneBackend::startSession：wantDirectSsh(o.transport, envDirect) → makeSshFactory
```

- `it2w::SshLaunchOptions`（`platform/windows/ssh/ssh_session_transport.h`）新增：

  ```cpp
  // 按连接选择的传输；nullopt = 全局默认（ITERM2WIN_SSH_DIRECT）。由窗格后端选工厂时读取，传输本身不看。
  std::optional<SshTransportMode> transport;
  ```

  `HyperVLaunch.ssh` 就是 `SshLaunchOptions`，Hyper-V 内层自动带上，不另加字段。

- `Win32PaneBackend`：
  - `sshDirect_` 改名为 `envSshDirect_`（仍在构造时读一次环境变量），含义是「全局默认」。
  - 新增 `attemptDirect_`：每次 `startSession` 的 SSH / Hyper-V 分支在建工厂前算出 `wantDirectSsh(o.transport, envSshDirect_)` 并存下。Hyper-V 分支里给快照错误改前缀的那段（现读 `p.sshDirect_`）改读 `attemptDirect_`。
  - 每次重连都重新走 `resolveSsh` / `resolveHyperV`，但它们读的是启动时载入内存的 connections.json；手改文件后要重启产品才生效（与其他连接字段一致）。

## 5. 校验与报错文字

`uicfg::validate`（SSH 连接）新增：

- `transport` 有值但不是 `"compatible"` / `"direct"`（含非字符串）→ `{"ssh.transport", "传输只能是 compatible 或 direct"}`。
- `transport == "direct"` 且 `authMode != Agent` → `{"ssh.auth.mode", "直连只支持 agent 认证；改用 agent，或把 ssh.transport 改为 compatible"}`。

只有环境变量开了 Direct、连接没写传输时，非 agent 认证照旧在启动前由 `validateDirectAuthMode` 拒绝。它的文字改成：

> 直连 v0 仅支持 agent；请 ssh-add 后使用，或在连接里写 "transport": "compatible"，或去掉 ITERM2WIN_SSH_DIRECT

`selectSshTransport` 的 `Unavailable` 文字改成：

> 此构建未包含直连 SSH；把连接的 ssh.transport 改为 compatible，或去掉 ITERM2WIN_SSH_DIRECT

两条文字都有现成单测在断言，跟着改。

## 6. 测试

平台无关，进 ctest：

- **store**：省略时读入 nullopt、保存后仍没有该字段；`"compatible"` / `"direct"` 往返；未知字符串、非字符串（数字、null、对象）读入后该连接校验失败、文件不变 Corrupt，且保存被拒绝；`describeLaunch` 对 manual 与 Hyper-V 都带出 transport。
- **validate**：未知值、非字符串 → `ssh.transport` 错误；`direct` + KeyFile / Interactive → `ssh.auth.mode` 错误；`direct` + Agent、`compatible` + KeyFile、省略 + KeyFile 都通过。`validateConnectionsFile` / `reportValidation` 能报出这两个新字段。
- **pane_logic**：`wantDirectSsh` 的 §3 真值表；`selectSshTransport` 与 `validateDirectAuthMode` 的新文字。

只能在 Windows 上验的（写进 STATUS「未验证」）：

1. 不设环境变量：写 `"transport": "direct"` 的连接走直连（pane-diag.log 有 `ssh.direct.*`，任务管理器里没有该窗格的 `ssh.exe`），其余连接仍是 `ssh.exe`。
2. 设 `ITERM2WIN_SSH_DIRECT=1`：写 `"transport": "compatible"` 的连接仍是 `ssh.exe`。
3. Hyper-V 连接写 `"direct"`：内层走直连，未知主机出现 DS-12 的「核对指纹…」。
4. 默认 `mingw` 构建（不含 Direct）里写 `"direct"`：窗格 Failed，文字如 §5。
5. `"direct"` + KeyFile：启动时状态栏报连接配置无效，窗格不启动。
6. CI `mingw` 与手动 `mingw-direct` 编译通过。
