# 终端身份（设计 14.3）

日期：2026-11-03  
范围：GAP-16 / REVIEW A′3。级别在 DECSLRM、矩形操作落地之前保持不动。

## 选择

对外级别是 **VT220**，不是 VT100，也不是 VT520。

| 请求 | 应答 | 含义 |
|---|---|---|
| DA1 `CSI c` / `CSI 0 c` | `CSI ? 62 ; 22 c` | 62 = VT220。22 = ANSI 颜色。不带 132 列、打印机、Sixel、选择性擦除、窗口操作、左右边距、矩形编辑、OSC 52 |
| DA2 `CSI > c` / `CSI > 0 c` | `CSI > 1 ; 0 ; 0 c` | Pp=1 是 VT220 的次级标识。Pv=0 表示这不是某个 xterm 补丁级别。Pc=0 |
| DA3 `CSI = c` / `CSI = 0 c` | `DCS ! \| 7465726d7632 ST` | `7465726d7632` 是 `termv2` 的小写十六进制。只为了让探测有稳定应答，**不**把级别抬到 VT420 |
| XTVERSION `CSI > q` / `CSI > 0 q` | `DCS > \| termv2 0.1 ST` | 仓库没有 `project(VERSION)`，用设计系列 `0.1` |
| 其它 Ps（例如 `CSI > 1 c`、`CSI > 1 q`、`CSI = 1 c`） | 无应答 | 只有省略或 0 才是查询 |

DA3 在 VT420 才出现。这里仍然应答，是因为保持沉默会让部分程序一直等到超时，而 Pp=1 本身并不承诺 DA3。应答文本是固定单元号，不是更高一级的能力表。

## 为什么补丁号是 0

先前的 DA2 是 `CSI > 64 ; 2500 ; 0 c`（VT520 + xterm 2500），和 DA1 的 VT100 互相矛盾，也会让程序以为左右边距和矩形操作已经存在。

补丁号也不用 2500 或 279：

- Vim 把 xterm 版本 `< 95` 当成“不是 xterm”，并保留下划线真彩色（`t_8u`）。版本 `≥ 95` 且 `< 2500` 会清掉 `t_8u`。版本 `< 279` 时 Vim 不主动探测光标样式，`< 141` 时不发 XTGETTCAP。
- Emacs 在版本 `≥ 216` 时打开 modifyOtherKeys，`≥ 242` 时查询背景色。这两项都还没实现。`Pp=1` 且版本 `> 2000` 会被 Emacs 先降到 200，但那是借用 2500 的副作用，不是诚实的补丁号。

Pv=0 同时满足：不宣称 xterm 补丁，Vim 仍保留下划线色，Emacs 不打开 modifyOtherKeys。鼠标 1006 已实现，但不借 xterm 277 来宣称。

## 查询

- **DECRQSS** 成功是 `DCS 1 $ r <数据><Pt> ST`，失败是 `DCS 0 $ r ST`（空数据，不回显 Pt）。已实现：`m`（笔状态，反显不交换颜色）、`r`（滚动区，1 基）、`SP q`（当前 DECSCUSR，含 0）、`"q`（DECSCA 固定 `0`，字符保护未实现）。截断的 DCS 走失败形式。
- **XTGETTCAP**（`DCS + q`）已知名区分大小写：`TN` / `name` = `termv2`，`Co` / `colors` = `256`，`RGB` = `8`（每通道 8 位）。成功 `DCS 1 + r <十六进制名>=<十六进制值> ST`。未知、奇数长度或非法十六进制：`DCS 0 + r ST`，不附名字。多个名字用 `;` 分开，每个名字一条 DCS。
- **DECRQM ?69**（DECSLRM）仍是 0（不认识）。左右边距实现之前不要改 DA 级别。
