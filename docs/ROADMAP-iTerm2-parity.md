# 对照 iTerm2 的功能补齐路线（设计提纲）

日期：2026-11-02  
基线：main `bcd7e9a`  
用途：列出 v0.1 之后对齐 iTerm2 还缺的能力，以及每项动手前必须先定的设计决策。本文只是提纲，不是设计本身：每项立项时各写一份设计或 ADR，把编号回填到「设计文档」一栏。  
相关文档：[REVIEW.md](../REVIEW.md) §3（初版差距表）、[ADR-002](ADR-002-CAP01-P06-osc52-read.md)、[ADR-003](ADR-003-ssh-direct.md)、[STATUS.md](STATUS.md)（CAP-01 第 16–18 轮）。

## 0. 使用约定

- **状态**：`[ ]` 未开始，`[~]` 有部分代码，`[x]` 已完成并经实机验收。
- **传输**：功能在哪些传输上可用。`C` = 本地 ConPTY；`S` = 兼容 SSH（ssh.exe 跑在 ConPTY 里，与 C 有同样的序列限制）；`D` = Direct SSH（libssh2 进程内直连，对控制序列透明）；`W` = 将来的 WSL 类型。
- **每项立项时补齐三样**：设计文档链接、验收用例编号、需要的实机场景。

### 0.1 硬约束：ConPTY 的序列透明度（实机结论）

| 序列 | 经 ConPTY（C/S） | Direct（D） | 来源 |
|---|---|---|---|
| OSC 133、OSC 1337 | 透传；OSC 133;A 位置正确 | 透传 | STATUS 第 16、17 轮 |
| OSC 8 | 被改写（加 `id=`，BEL 改成 ST） | 透传 | 第 16 轮 |
| DCS（tmux -CC、XTGETTCAP、DECRQSS）、Sixel | **被吞** | 透传 | 第 16、18 轮 |
| OSC 52 读 | 不支持 | 通道透明，但 `supportsOsc52Read=false`（D-1，待逐次确认 UI） | ADR-002 |

结论：依赖 DCS 或 Sixel 的功能只能在 `D` 上提供。本地 cmd 和 PowerShell 永远拿不到这些功能，界面必须明确提示「当前连接不支持」，不能静默失效。

### 2.4 tmux 集成（tmux -CC）

## 3. 不做或放远期

- 即时回放（DVR）、8 位 C1 控制、DECDHL/DECDWL 双宽双高行。
- iTerm2 3.5 的 AI 辅助与 Composer：核心稳定后再评估。
- macOS 专属功能（Secure Keyboard Entry、Touch Bar 等）：Windows 上没有对应物。
