# DS-18 字形运行渲染：设计审查意见

审查对象：[DS-18-字形运行渲染.md](DS-18-字形运行渲染.md)，2026-11-05 第 1 版。

**处理状态（2026-11-05）**：全部意见已在 DS-18 第 2 版的设计中处理，对照表见 DS-18 §12，每条下面注明对应章节。设计仍待批准，尚未实现。

结论：按段塑形、按核心格定位、缓存塑形结果的方向可行，但下列契约需要在实现前明确。本清单仅记录设计审查意见；P1 为正确性阻断项，P2 为需要补齐的行为、兼容性或验收约定。

## P1：正确性阻断项

- [x] **补齐 script 分析和文本方向策略（§4.1–4.3、§10）。**
  - `MapCharacters` 解决字体回退，不替代 script 分析；同一个字体子段也可能包含多个 script。`GetGlyphs` 需要来自 `AnalyzeScript` 的 `scriptAnalysis`，设计当前没有分析步骤、sink 或 script 边界。
  - 必须明确终端采用逻辑列顺序还是 bidi 视觉顺序，以及 `isRightToLeft`、绘制时 `bidiLevel` 和 `clusterMap` 的处理约定。“每簇首字形在首列左缘”不能直接覆盖 RTL 运行。
  - 建议：写明 script/方向分析与字体回退区间如何求交；如果首版不支持 bidi 重排，明确边界和降级方案，删去复杂文字“不会更差”的无条件承诺。补充阿拉伯文、天城文和混合 script 用例。
  - 依据：[GetGlyphs 参数契约](https://learn.microsoft.com/en-us/windows/win32/api/dwrite/nf-dwrite-idwritetextanalyzer-getglyphs)。
  - **设计已处理**：DS-18 第 2 版 §4.2：`AnalyzeScript` 与 `MapCharacters` 的区间求交，得到塑形项；不做 bidi，全部从左到右，`bidiLevel = 0`；RTL script 逐格塑形降级；删掉「不会更差」的说法；补了求交单测，以及阿拉伯文、天城文、混排手测。

- [x] **处理一个核心字素格对应多个塑形簇的情况（§4.3）。**
  - 当前规则给每个塑形簇分配它涉及的列宽，再把总 advance 改为该宽度。如果一个核心字素因字体回退、script 分割或字体不支持组合而形成多个塑形簇，它们的 `cellOfChar` 可能指向同一列。
  - 例如同一格的基字符和组合符分别落入两个簇：两个簇都得到一格 advance，顺序累加就不再等于后一个簇自己的首列。跨字体子段重新定位时也缺少共同的格内锚点。
  - 建议：明确核心字素与塑形簇是多对多关系；按绝对列锚定位置，定义共享格的多个簇如何定位、共同裁剪及计算缩放，避免重复计宽。除现有“一个簇多个字形”测试外，增加“一个核心格多个塑形簇”和“一个核心格跨字体子段”的测试。
  - **设计已处理**：DS-18 第 2 版 §5.1–5.2：改按「定位单元」（塑形簇连接各列形成的连通分量）定位，单元内按绝对笔位累加，跨塑形项同样成立；超宽时整个单元一起缩放；补了「同一核心格两个簇」和「同一核心格跨两个塑形项」的单测。

- [x] **补齐块光标断段导致的脏行失效与反色重画策略（§3、§4、§9）。**
  - 当前渲染器把文本保存在持久画布，光标主要是覆盖层。设计让底层塑形依赖光标位置，却没有要求光标移动、闪烁、焦点、形状或 IME 状态变化时重画文本行。
  - 只重画覆盖层会留下旧位置的断开的连字，新位置仍可能保留完整连字。光标落在宽字尾格时，也必须先吸附到首格并隔离整个宽字。
  - 建议：明确断段条件改变时同时标脏旧、新光标行；定义闪烁隐藏相位是否恢复连字；光标反色字形复用同一份塑形、定位和缩放结果，不能默认旧 `DrawTextW` 重画必然匹配。增加“内容 revision 不变，仅移动/闪烁光标”的测试。
  - **设计已处理**：DS-18 第 2 版 §7：隔离条件只看 DECTCEM、块形状和预编辑，与闪烁相位、焦点无关；隔离状态变化时旧行、新行都标脏；宽字符吸附到首格；反色字形改走同一条塑形和定位路径；补了 `isolateDirtyRows` 单测。

- [x] **统一 DIP 与物理像素坐标（§4.2–4.4）。**
  - `ShapedGlyphs.advances` 标为 DIP，`originX` 和容差是像素，`cellW` 单位未定义。现有渲染器字号已乘 DPI，在物理像素画布上绘制。直接按文档相减比较会在非 100% DPI 时错误判断超宽、缩放和基线。
  - 建议：选择单一定位单位，写明字号、fallback scale、advance、offset、格宽、baseline、绘制上下文 DPI 和变换矩阵的转换点；保证 DPI 只应用一次。至少覆盖 100%、125%、150%、200% 及跨屏切换，并验证 1 px 容差不会变成 1 DIP。
  - **设计已处理**：DS-18 第 2 版 §3：全部改用物理像素，D2D 上下文保持 96 DPI，DPI 只在字号处乘一次；纯函数参数统一带 `Px` 后缀；单测和手测都覆盖四档缩放。

## P2：行为和验收约定

- [x] **消除连字关闭时的分段矛盾（§3、§4.2）。**
  - “每个字素簇自成一段”与“同段的多个簇仍可以合并”“开关只影响塑形特性”互相矛盾；`segmentRow` 签名也没有连字参数。
  - 建议明确采用“同样式连续格合段，关闭时禁用 liga/calt/clig”，或者定义独立的逻辑断点与批量塑形结构。还需区分可选连字与复杂文字必需的塑形，不能把关闭这三个特性描述为禁止一切跨字素塑形。
  - **设计已处理**：DS-18 第 2 版 §4.1、§4.3：分段与连字开关无关，关闭连字只禁用 `liga` / `calt` / `clig`；并说明复杂 script 必需的塑形不受影响。

- [x] **修正整段裁剪等同逐格裁剪的承诺（§4.3–4.4、§9.1）。**
  - 整段裁剪允许斜体、负 side bearing 或零 advance 标记越过相邻格边界；逐格裁剪会截掉它们。自然 advance 小于格宽也不代表实际墨迹不越界。
  - 建议明确哪些跨格墨迹允许保留，以及背景/选区/搜索/隐藏格边界如何限制绘制；将验收改成明确的允许差异，或对必要的簇增加格级裁剪。加入斜体邻接空格、不同背景与选区边缘的图像用例。
  - **设计已处理**：DS-18 第 2 版 §5.4：明确「段内允许墨迹越格，段边界处裁掉」；分段同时按背景色断开，让裁剪边界与背景边界一致；手测列出了需要检查的边缘。

- [x] **补全塑形缓存值和超宽簇绘制的接口契约（§4.3、§5）。**
  - 当前 `ShapedGlyphs` 未包含 glyph indices；`ShapedRun` 子段缺少文本起始位置/长度、实际 em size 与方向；`ScaledCluster` 未定义。仅凭列出的数据不能可靠构造 `DWRITE_GLYPH_RUN` 或把子段映射回原段字符。
  - “从本次绘制拿出来”需明确为拆分绘制区间或其他不重复绘制的办法：不能只移除 advance，否则后续字形会移位；只把 advance 置零也不会隐藏字形。
  - 建议定义 glyph/UTF-16 范围、缩放原点、裁剪矩形和正常绘制片段；缓存只保存与列坐标无关的塑形数据。补齐字节计费、单项超过 4 MiB 时绕过缓存、`find` 返回指针的有效期，以及 `GetGlyphs` 缓冲不足时扩容重试和有界失败策略。
  - 依据：[GetGlyphs 缓冲区与返回值约定](https://learn.microsoft.com/en-us/windows/win32/api/dwrite/nf-dwrite-idwritetextanalyzer-getglyphs)。
  - **设计已处理**：DS-18 第 2 版 §5.4 `DrawPiece`、§8 `ShapedItem`：补全字形下标、文本区间、字号和 script；超宽单元拆成独立片段，前后片段各自用绝对原点；补了计费、单项绕过、指针有效期，以及 `GetGlyphs` 的扩容重试和有界失败。

- [x] **限定彩色字体支持范围并定义前景色层行为（§4.5、§9）。**
  - Factory2 的分层路径不能据此承诺所有彩色字体格式都支持；SVG、位图以及较新的彩色绘制格式需要额外能力。还应区分字体固定色层与使用当前前景色的层，不能无条件使用每层给出的颜色。
  - 建议明确首版支持的格式、系统/字体版本和不支持时的单色降级；写明 `paletteIndex == 0xFFFF` 使用当前前景画刷，以及块光标反色、DIM、选区与固定彩色层的关系。测试固定色层和前景色层混合，且不要只用 ASCII 的颜色测试替代彩色字体验收。
  - 依据：[DWRITE_COLOR_GLYPH_RUN](https://learn.microsoft.com/en-us/windows/win32/api/dwrite_2/ns-dwrite_2-dwrite_color_glyph_run)、[TranslateColorGlyphRun 格式选择](https://learn.microsoft.com/en-us/windows/windows-app-sdk/api/win32/dwrite_3/nf-dwrite_3-idwritefactory8-translatecolorglyphrun)。
  - **设计已处理**：DS-18 第 2 版 §6：首版只支持 COLR v0，其他格式单色降级并记为已知限制；`paletteIndex == 0xFFFF` 用当前文本颜色，固定色层不受反色、DIM 和选区影响。

- [x] **保留可比的旧路径性能基线，明确统计分母（§5、§8）。**
  - 文档一边要求删除 `I.advance[4]`，一边保留旧路径进行耗时对比。如果旧路径因此每格重新量宽，会人为拖慢基线，无法证明新路径优于当前实现。
  - 每帧文本 p95 混入大量仅更新光标的帧，也不能证明“满屏重画 p95 ≤ 8 ms”；D2D 绘制调用计时主要反映 CPU 提交成本，不等于 GPU 完成或端到端延迟。
  - 建议旧路径保留等价量宽缓存；分别统计无文本重画、部分行和全屏重画，区分冷/热缓存，定义样本上限、窗口重置和命中率分母。日志注明路径、连字、DPI、网格及重画行数；明确 8 ms 指标测的是哪段 CPU 工作，并将 GPU/端到端性能作为独立验证。
  - **设计已处理**：DS-18 第 2 版 §9：旧路径原样保留，包括量宽缓存；分无文本、部分、全屏三类统计，并区分冷、热窗口；写明命中率的分母和每条记录的上下文；8 ms 只约束文本 CPU 提交时间，GPU 和端到端另测。
