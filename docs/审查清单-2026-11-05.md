## 问题（2026-11-05 已修复）

- [x] **P1：ConPTY 关闭完成前未保证写线程退出**
  - 位置：`platform/windows/conpty/conpty_transport.cpp:380–383`，以及 `doClose()` 的最终通知和析构函数。
  - 问题：取消写线程约 1 秒后仍未退出时，仅记录 `writer-cancel-timeout`，随后继续清理并发送 `closedEvent_`。析构函数关闭线程句柄，但没有再次等待写线程退出。
  - 触发条件：写线程在取消等待超时后延迟恢复，且 transport 已被释放。
  - 影响：写线程可能继续访问 `input_`、`lock_` 或 `inWrite_`，存在 use-after-free 风险。
  - 修复建议：终止进程、关闭 ConPTY 后再次等待写线程退出；只有所有访问 transport 的工作线程退出后，才公布关闭完成并允许析构。
  - 验收：注入延迟退出的写线程，验证 `waitClosed()` 不会提前成功，销毁期间没有线程继续访问对象。
  - 证据状态：静态代码分析，尚未 Windows 实机复现。
  - 修复：`ClosePseudoConsole` 之后循环 `CancelSynchronousIo` 并等待写线程退出，然后才置位 `closedEvent_`（另记 `close.writer-join`）。析构函数关闭句柄前先等待 closer、writer、monitor、reader 退出。顺带修复两处：monitor 改在关闭 `process_` 之前 join，以前 monitor 可能仍在等待一个已关闭的句柄；没有写线程时由 `doClose` 关闭 `inWrite_`，以前会泄漏。仅静态复查，待 CI MinGW 编译和 Windows 实机验证。

- [x] **P2：关闭线程创建失败时，同步兜底可能自等待死锁**
  - 位置：`platform/windows/conpty/conpty_transport.cpp:359–360`；`doClose()` 中等待 reader 和 monitor 的逻辑。
  - 问题：`CreateThread` 失败后直接在调用线程执行 `doClose()`，但 `close()` 可能由 reader 或 monitor 线程调用；清理流程又会无限等待这些线程结束。
  - 触发条件：reader 或 monitor 发起关闭，同时 closer 线程创建失败。
  - 影响：调用线程等待自己结束，关闭流程卡死，`closedEvent_` 无法触发。
  - 修复建议：由独立生命周期管理线程执行清理，避免工作线程同步执行包含自身 join 的流程；不能仅跳过等待后就释放仍被工作线程使用的对象。
  - 验收：故障注入 closer 创建失败，分别覆盖 reader 和 monitor 发起关闭，验证无自等待且对象生命周期安全。
  - 证据状态：静态代码分析，尚未 Windows 实机复现。
  - 修复：closer 改为常驻线程，在 `start()` 第 11 步、writer 和 monitor 之前创建，等待 `closeRequest_` 事件；`close()` 只置位该事件，任何线程都不会自己执行 `doClose`。closer 创建失败时，只有读线程在运行，由 `start` 的调用线程同步收口（先占住 `closeStarted_`）。仅静态复查，待 Windows 验证。

- [x] **P2：Ctrl 符号组合键缺少控制字符映射**
  - 位置：`ports/core/src/encode.cpp:60–68`，`ctrl_letter()`。
  - 问题：只处理字母、空格和问号，其他符号回退为普通 UTF-8 字符。
  - 影响：Vim 的 `Ctrl+[` 及其他依赖控制字符的交互失效。
  - 修复建议：补全控制字符映射，并增加 `planKey → encode_key` 链路回归测试。
  - 验收：以下组合键输出预期字节，同时检查 Ctrl/Alt/Shift 组合和 AltGr 输入没有回归。
  - 证据状态：已通过调用本次构建的核心编码接口复现。
  - 修复：`ctrl_letter` 把 `@`–`_`（0x40–0x5F）统一映射为 `cp & 0x1F`，原有的字母、空格、`?` 行为不变，不增加数字键别名。`test_encode` 覆盖 6 个符号、Ctrl+Alt+[ 和 Ctrl+1；`test_pane_logic` 覆盖 `planKey` 链路（Ctrl+[、Ctrl+Shift+6、德语 AltGr+8 仍按文本输入），以及 planKey→`itcore_encode_key` 端到端用例。
