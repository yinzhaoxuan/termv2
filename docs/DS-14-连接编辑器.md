# DS-14 连接编辑器（D1）

日期：2026-11-04
基线：main `d638d60`
出处：`REVIEW.md` GAP-07（「先补一个最小编辑器，能完成『新建 Ubuntu 连接 → 保存 → 连接 → 编辑 → 再次连接』」）、§8 D1；`docs/TODO.md` §2.2；DS-9 §1、DS-13 §1 留给本文的「给连接选外观 Profile / 传输」。

凡写「决定」的地方，是本文替原设计补的选择。

## 0. 现状

- 会话树（`refreshTree`）只能双击 / 回车打开连接。没有右键菜单，没有任何对话框；`it2w_shell.rc` 只有 manifest。
- 模型已有：`uicfg::validate` / `validateInFile` / `validateConnectionsFile`、`saveConnections`（任一连接校验失败即拒绝保存；先写临时文件再替换，留 `.bak`）、`deleteConnection`、`updateConnection`。主程序从不调用 `saveConnections`。
- connections.json 只在启动时读一次（`wWinMain`），之后存在 `g->conns`。`describeLaunch` 每次连接 / 重连都读 `g->conns`，所以内存里的修改对之后的连接立即生效。
- Hyper-V：`it2w::listHyperVVms(timeoutMs, cancel)` 运行固定 PowerShell 脚本列出 VM 与网卡（`platform/windows/hyperv/hyperv_query.h`），可能要几秒。

## 1. 目标与边界

做（验收即 GAP-07 那条路径）：

1. 新建连接：SSH 手动地址、SSH Hyper-V、本地程序三种。
2. 编辑连接：上述字段，加分组、外观 Profile（DS-9）、SSH 传输（DS-13）。
3. 删除连接。
4. 分组：新建、重命名、删除（组内连接变为未分组）；在编辑器里改连接的分组。
5. 保存到 connections.json；会话树刷新；之后新建 / 重连的窗格用新配置。

不做：

- 拖拽排序、分组排序、复制连接、导入导出。
- 本地连接的环境变量编辑（`environment` 原样保留，编辑器里只显示一行说明「环境变量请在 connections.json 中编辑」）、`closePolicy` 编辑（原样保留）。
- 外观 Profile 的编辑（只选择 ID）。
- 已打开窗格不重连、不改标题（运行中会话用启动时的快照，`SessionSnapshots` 语义不变）。唯一的例外是配色：改了外观 Profile 后，该连接已打开的窗格按 DS-9 §5.2 实时换色。

约束同前：逻辑放 `ui/src`（uicfg）并单测；`main.cpp` 和 `.rc` 只做界面与接线；不改 core、不改 Direct 默认值。

## 2. 入口：会话树右键菜单（决定）

`NM_RCLICK` 时先把右键命中的项设为选中（`TVM_HITTEST` + `TreeView_SelectItem`），再弹菜单。菜单内容由纯函数决定：

```cpp
enum class TreeTarget { Empty, LocalShell, Group, Ungrouped, Connection };
enum class TreeAction { Connect, NewConnection, EditConnection, DeleteConnection, NewGroup, RenameGroup, DeleteGroup };
struct TreeMenuItem { TreeAction action; std::string label; bool enabled; };  // label 含「…」
std::vector<TreeMenuItem> treeMenuFor(TreeTarget target, bool readOnly);
```

| 目标 | 菜单（顺序） |
|---|---|
| 连接 | 连接 / 编辑… / 删除… / ─ / 新建连接… / 新建分组… |
| 分组 | 在此分组新建连接… / 重命名分组… / 删除分组… / ─ / 新建分组… |
| 未分组 | 新建连接… / 新建分组… |
| 本地终端、空白处 | 新建连接… / 新建分组… |

- 分隔线用 `label` 为空的项表示（`TreeAction` 取任意值，`enabled=false`），`main.cpp` 遇到空 label 插 `MF_SEPARATOR`。
- `readOnly`（connections.json 为高版本 / 损坏）时，除「连接」外全部 `enabled=false`，并且菜单最后多一项禁用的「connections.json 只读，无法编辑」。
- 键盘：会话树获得焦点时 `F2` = 编辑选中连接 / 重命名选中分组，`Delete` = 删除；`Shift+F10` / 菜单键弹出同一菜单（`WM_CONTEXTMENU` 的坐标为 -1 时取选中项矩形）。

`App::TreeNode` 目前只有 `isGroup` + `id`；「未分组」用 `isGroup && id.empty()` 区分，「本地终端」用 `!isGroup && id.empty()`。映射到 `TreeTarget` 写成 `main.cpp` 里的小函数即可。

## 3. 编辑器对话框

### 3.1 资源

- 新文件 `ui/shell_win32/resource.h`：控件 ID（`IDD_CONNECTION`、`IDC_NAME` …）。
- `it2w_shell.rc`：加 `#include "resource.h"`、`#pragma code_page(65001)`（文件存 UTF-8 无 BOM），两个 `DIALOGEX` 模板：`IDD_CONNECTION`（编辑器）与 `IDD_TEXT_PROMPT`（分组名输入：一个静态文本、一个编辑框、确定 / 取消）。字体 `FONT 9, "Microsoft YaHei UI"`。
- 用 `DialogBoxParamW(inst, MAKEINTRESOURCEW(IDD_CONNECTION), g->main, ConnectionDlgProc, (LPARAM)&state)`，模态。Tab 顺序按模板里控件的顺序。
- 窗口为 Per-Monitor V2：对话框模板由系统按 DPI 缩放，不额外处理。

- SSH 区和本地区占同一块位置，按「类型」显示其一（`ShowWindow`）；手动地址 / Hyper-V 两行同理。隐藏的控件**保留**已填内容，切回来还在；保存时只读当前类型的字段。
- 「外观」列表：`appearance-default` 在第一项，其后为 `g->settings.appearanceProfiles` 的键（按字典序，去重）。连接当前的 ID 若不在其中，也列出并加后缀「（未定义）」，保存时原样保留。
- 「网卡」列表：第一项「自动」（= `adapterId` 为空）；连接已有 `adapterId` 时列出该 ID；用「选择…」挑过 VM 后，换成该 VM 的网卡（显示 `名称 · MAC`，值为网卡 ID）。
- 「地址族」不进界面（`ipv4` 默认，原值保留）。`hostScope` 同理。

### 3.3 Hyper-V「选择…」

- 点击后按钮变「正在查询…」并禁用，启动一个 `std::thread`（detach）调用 `listHyperVVms(15000, cancelEvent)`。
- 线程结束时 `PostMessageW(dlg, WM_APP_VMLIST, 0, (LPARAM)new HvQueryResult(...))`；`PostMessageW` 失败（对话框已关闭）就 `delete`。对话框 `WM_DESTROY` 时 `SetEvent(cancelEvent)`；事件句柄由线程和对话框共享（`std::shared_ptr` 包一层，最后一个持有者 `CloseHandle`）。
- 收到结果：失败 → 错误行显示原因（文字由纯函数 `uicfg::hyperVListError(HvQueryError 名称, msg)` 给出：模块缺失 / 无权限 / 超时 / 其他）；成功且有 VM → 在按钮下弹 `TrackPopupMenu`，每项 `名称（状态）`，选中后填 VM ID、换网卡列表；0 个 VM → 错误行「没有找到虚拟机」。
- 占位后端构建（`IT2W_SHELL_STUB_BACKEND`）没有 `it2w_hyperv`：按钮禁用。

### 3.4 确定

1. 从控件读出 `ConnectionForm`（§4），`applyConnectionForm` 得到 `Connection` 或字段错误。
2. 再跑 `validateInFile(next, c)`（含 DS-13 的传输 / 认证组合）。
3. 有错误：错误行显示第一条「字段：说明」，焦点移到该字段对应的控件（`main.cpp` 里一张 `field → 控件 ID` 表，找不到就不动焦点），对话框不关。
4. 无错误：把连接放进 `ConnectionsFile` 的**副本**，调 `saveConnectionsChecked`（§6）。失败：错误行显示原因，对话框不关；成功：`g->conns = 副本`，关对话框，`refreshTree()`，状态栏「已保存连接「名称」」。若外观 Profile 变了，对该连接已打开的窗格调 `setColors`（DS-9 §5.2 的同一函数）。

「取消」/ Esc：不保存，不提示（v1 不做「有未保存修改」的确认）。

## 4. 表单模型（`ui/include/uicfg/connection_form.h`，新文件）

```cpp
enum class FormKind { SshManual, SshHyperV, Local };
struct ConnectionForm {
  std::string name, groupId, appearanceProfileId;
  FormKind kind = FormKind::SshManual;
  // SSH
  std::string host, port = "22", user;
  AuthMode auth = AuthMode::Agent;
  std::string identityFile;
  std::optional<SshTransport> transport;   // nullopt = 跟随全局默认
  std::string connectTimeout = "15";
  // Hyper-V
  std::string vmId, adapterId, fallbackHost;
  // 本地
  std::string executable, argumentsText, workingDirectory;   // argumentsText：每行一个参数
  bool argumentsEditable = true;   // false：原参数表单表示不了（§4），沿用 base
};

ConnectionForm formFromConnection(const Connection&);
ConnectionForm newConnectionForm(const std::string& groupId);  // 新建：appearance-default、agent、端口 22、超时 15

struct FormApplyResult { std::optional<Connection> connection; std::vector<ValidationError> errors; };
// base：编辑时为原连接（保留 id、order、environment、closePolicy、addressFamily、hostScope 等编辑器不管的字段，
//      以及非法的 transport 原文——若表单 transport 未改动）；新建时为 nullopt，由 cf 分配 id 与 order。
FormApplyResult applyConnectionForm(const ConnectionForm&, const std::optional<Connection>& base, const ConnectionsFile& cf);
```

规则（决定）：

- 文本字段去首尾空白（名称、主机、用户名、VM ID、回退地址、程序、工作目录、密钥文件）。**参数不去空白**，只去掉每行末尾的 `\r`。
- `argumentsText`：按 `\n` 切分，每行一个参数，**空行丢弃**。`formFromConnection` 反过来用 `\r\n` 连接（多行编辑框需要 CRLF）。
- 表单表示不了的参数：原连接有参数含 `\r` / `\n`，或有空字符串参数（这两种在 Windows 命令行里都合法，校验不拒绝）。此时 `formFromConnection` 置 `argumentsEditable = false`，对话框把参数框设为只读并在下方说明「参数含换行或空参数，请在 connections.json 中编辑」；`applyConnectionForm` 在 `!argumentsEditable` 时原样沿用 `base` 的参数。`ConnectionForm` 因此多一个字段 `bool argumentsEditable = true;`。
- 端口、超时：必须是十进制整数（允许前后空白），否则错误字段为 `endpoint.port` / `ssh.connectTimeoutSeconds`，文字与 `validate` 一致（「端口必须是 1–65535 的整数」等）。范围检查交给 `validate`。
- 空的可选字段变 `nullopt`：Hyper-V 的 `adapterId` / `fallbackHost`、本地的 `workingDirectory`、非密钥文件认证时的 `identityFile`（切换认证方式时不保留旧路径）。
- 类型切换：SSH ↔ 本地时清掉另一侧（`endpoint` / `ssh` / `local` 三者只留对应的）；手动 ↔ Hyper-V 时清掉 `host` / `hyperv`。`local.environment` / `closePolicy` 只在原连接本来是本地时从 `base` 继承，否则用默认。
- `transport`：表单值与 `parseSshTransport(base->ssh)` 相同（含两者都是 nullopt），且 `base` 有原文时，保留原文（这样非法原文不会被悄悄改掉，校验照旧报错，用户必须在下拉框里选一个才能保存）。否则按表单写 `"compatible"` / `"direct"` / 省略。
- 新连接：`id = newConnectionId(cf)`，格式 `conn-<十进制>`，从 1 起找第一个未被占用的；`order` = 目标分组内现有最大 `order` + 1（空组为 0）。改了分组的已有连接同样放到新组末尾；分组没变则 `order` 不变。

## 6. 保存与外部修改

connections.json 只在启动时读入。若用户在程序运行时手改了文件，编辑器保存会悄悄覆盖手改的内容。决定：**检测到外部修改就拒绝保存**，提示重启。

```cpp
struct FileStamp { bool exists = false; std::uintmax_t size = 0; std::filesystem::file_time_type mtime{}; bool operator==(const FileStamp&) const = default; };
FileStamp fileStamp(const std::filesystem::path&);
// 先比较当前磁盘戳与 expected：不同 → false，*error = "connections.json 已在程序外被修改；为避免覆盖，请重启后再编辑"。
// 相同 → saveConnections；成功后把 *expected 更新为新文件的戳。
bool saveConnectionsChecked(const std::filesystem::path&, ConnectionsFile&, bool readOnly, FileStamp* expected, std::string* error);
```

- `App` 新增 `FileStamp connsStamp`：`loadConnections` 之后立刻 `fileStamp(path)` 记下。文件不存在时 `exists=false`，第一次保存会创建它。
- `.bak` 照旧由 `saveConnections` 维护。
- `saveConnections` 本身「任一连接非法即拒绝」的规则不变。所以文件里有手改坏的其他连接时，保存会失败，错误行显示「连接 <id> 校验失败: …」。用户可以在编辑器里打开那条连接改好（会话树里非法连接照常显示）。

## 7. 测试

平台无关，进 ctest（新 `ui/tests/connection_form_tests.cpp`，按模式拆成多个 ctest 名）：

- **表单往返**：三种类型各一个完整连接 → `formFromConnection` → `applyConnectionForm`（base 为原连接）→ 与原连接相等（含 environment、closePolicy、addressFamily、hostScope、appearanceProfileId、transport 原文）。
- **字段解析**：端口 / 超时非数字、带空白、超范围；空可选字段变 nullopt；切换认证方式丢掉 identityFile；参数多行（CRLF / LF、空行丢弃、行内空白保留）；类型切换清掉另一侧；非法 transport 原文在表单未改时保留、改了就替换。
- **新建**：`newConnectionId` 跳过已占用的 `conn-1`、`conn-3`；order 放在组末尾；改分组后放到新组末尾。
- **分组**：`groupNameError` 的各条；`addGroup` 的 id 与 order；`renameGroup`；`deleteGroup` 移出连接并返回数量。
- **菜单**：`treeMenuFor` 每种目标、只读时的禁用与提示项。
- **文案**：`deleteConnectionPrompt` / `deleteGroupPrompt` / `hyperVListError`。
- **外部修改**：`saveConnectionsChecked` 在文件被改（内容、大小、mtime 任一）后拒绝；未改时保存成功并更新戳；文件原本不存在时能创建。mtime 精度不够时测试先改大小，不依赖 sleep。
- **不可编辑的参数**：含换行 / 空字符串参数的连接 → `argumentsEditable=false`，改其他字段后参数原样保留。

只能在 Windows 上验的（写进 STATUS「未验证」）：

1. GAP-07 路径：右键空白处「新建连接…」→ 填 Ubuntu 主机 → 确定 → 会话树出现 → 双击连接成功 → 右键「编辑…」改端口或用户名 → 确定 → 新开标签按新配置连接；已开的窗格不变。
2. Hyper-V：「选择…」列出 VM（未提权 / 无 Hyper-V 时显示对应错误），选中后网卡列表更新，保存后能连接。
3. 本地程序：浏览选择 `pwsh.exe`，参数两行，工作目录留空 → 启动在用户主目录。
4. 校验：端口填 `abc`、直连 + 密钥文件 → 错误行提示、焦点落在对应控件、对话框不关。
5. 分组：新建、重命名、删除（连接移到未分组）；树的展开状态不乱。
6. 删除连接时有运行中的窗格：窗格继续运行。
7. 程序运行时用记事本改 connections.json，再在编辑器保存 → 拒绝并提示重启；`.bak` 正常。
8. 只读（把 schemaVersion 改成 99 后启动）：菜单项禁用并有提示。
9. 高 DPI（150%）下对话框不裁切；Tab 顺序合理；Esc 取消。
10. CI `mingw` 编译通过（`.rc` 的 UTF-8 中文由 windres 处理，这是本文最大的编译风险）。
