# DS-18 字形运行渲染（E8）

日期：2026-11-05（第 4 版：第 2 版按首轮审查修订，见 §12；第 3、4 版按复审修订，见 §13、§14）
状态：已批准（2026-11-05，四轮审查后），实现中
出处：`REVIEW.md` §8 E8（「GlyphCache 图集与 glyph run 渲染路径，也是连字的前提」）、REVIEW §2 连字一行、`docs/HISTORY-2026-10.md`「未接：GlyphCache 图集与 plan_runs 多 face 回退」、`renderer/DESIGN-T06-渲染方案-v0.1.md` §3 第 4、5 条。审查意见：[首轮](审查清单-2026-11-05-DS-18.md)、[复审](审查清单-2026-11-05-DS-18-复审.md)、[三审](审查清单-2026-11-05-DS-18-三审.md)。

凡写「决定」的地方，是本文替原设计补的选择。

## 0. 现状

`D2DRenderer`（`renderer/d2d/renderer.cpp`）的文本遍历是逐格的：

- 每个非尾格：快照字素（UTF-8）→ `MultiByteToWideChar` → `DrawTextW`（四个 `IDWriteTextFormat` 之一，按粗 / 斜选），裁剪到该格。
- 为了 `fit_glyph`（宽于格的字形只缩不放、居中），首次遇到某个字素时用 `CreateTextLayout` 量 advance，按样式缓存在 `I.advance[4]`（超过 4096 条整表清空）。
- 字体回退靠 `DrawTextW` 内部的 DirectWrite 系统回退。
- `D2D1_DRAW_TEXT_OPTIONS_NONE`：彩色字体按单色画，emoji 是黑白的。
- 块光标（`cursor_inverts_glyph`）在覆盖层里对光标格再 `DrawTextW` 一次反色字形。
- 画布按物理像素绘制：D2D 上下文保持默认 96 DPI（1 DIP = 1 像素），`CreateTextFormat` 的字号是 `pt × 96/72 × dpi_scale`。
- `renderer/layout/glyph_cache.h` 里的 `GlyphCache`（LRU + shelf 图集）和 `plan_runs` / `pick_face`（自定回退链）有单测，但**渲染从未使用**。

问题：

1. **没有连字。** 逐格 `DrawTextW` 不跨格塑形。
2. **开销可能大。** 每格一次 `DrawTextW` 要走一遍 DirectWrite 的排版，满屏重画就是上万次调用。还没有实测数字，§9 先补度量。
3. **emoji 单色。**

## 1. 目标与边界

做：

1. 渲染改为**按段塑形、按格定位**：同样式、同颜色的连续格合成一段，DirectWrite 一次完成 script 分析、回退和塑形，再把字形钉到核心给的格子上。列数仍只由核心的 width / CONTINUATION 决定（规格 14.2）。
2. **连字可选**，默认关。
3. COLR v0 彩色字形（Segoe UI Emoji）按彩色画。
4. 塑形结果缓存；可移植部分（分段、定位单元、绘制片段、缓存、光标断段失效）做成纯函数，在 macOS / Linux 上单测。
5. 旧路径原样保留一个版本，可以切回，作为对比基线和退路。

不做：

- **不做位图图集**（决定，§2）。
- **不做双向文字（bidi）重排**（决定，§4.2）。终端按逻辑列顺序显示，所有塑形都按从左到右进行。
- 不改背景、光标框、下划线、删除线、上划线、选区和搜索高亮的画法（都是按格画矩形）。
- 不改预编辑（IME）覆盖层，仍用 `DrawTextW`。
- 不做字体回退链配置（F-1）、ClearType 开关、SVG / 位图 / COLRv1 彩色字体（§6）。

## 2. 为什么不做图集（决定）

原设计（T06 §3 第 5 条）想把字形光栅化进 D2D 位图图集，再逐格 `DrawBitmap`。现在改为 `ID2D1DeviceContext::DrawGlyphRun`：

- D2D 自己有按设备上下文的字形光栅缓存。推测的主要开销是 `DrawTextW` 每次的排版，不是光栅化；§9 的度量用来验证这一点。
- 位图图集画出来是灰度位图：失去 D2D 的文本抗锯齿和伽马处理，彩色字形要另走一套。Windows Terminal 的 AtlasEngine 用 D3D 着色器做，是另一个量级的工程。
- 设备丢失、DPI 失效、显存预算，D2D 已经处理。

`GlyphCache` 的图集部分和 `plan_runs` / `pick_face`（与 DirectWrite 系统回退重复）在新路径落地后删除，连同其单测；`fit_glyph` 保留。只有 §9 的实测证明光栅化是瓶颈时，才重新考虑图集。

## 3. 坐标单位（决定）

**全部用物理像素，DPI 只在字号处乘一次。**

| 量 | 单位与来源 |
|---|---|
| D2D 上下文 DPI | 保持 96（现状），1 DIP = 1 像素，不调用 `SetDpi` |
| 基准字号 `emPx` | `size_pt × 96/72 × dpi_scale`，与现在 `CreateTextFormat` 相同 |
| 回退字号 | `emPx × MapCharacters 返回的 scale`，只乘这一次 |
| advance、offset | `GetGlyphPlacements(fontEmSize = 上面的字号)` 的返回值，即像素 |
| 格宽、格高、基线 | `GridMetrics::cell_w_px()`、`cell_h_px()`、`baseline_px()` |
| 容差 | `kGlyphFitTolerancePx = 1`，像素 |
| 变换矩阵 | 只用于超宽单元的水平缩放（§5.3），以像素为单位 |

纯函数的参数和返回值一律标 `Px` 后缀。测试覆盖 100% / 125% / 150% / 200%，验证 1 像素容差在各缩放下都是 1 像素。

## 4. 分段与分析

### 4.1 分段（纯函数）

```cpp
struct TextCellIn {           // 每列一项（含尾格）
  std::u16string text;        // 字素的 UTF-16；空格子为 u" "；尾格为空串
  uint8_t width = 1;          // 1 或 2；尾格为 0
  uint8_t format = 0;         // 0..3：bold | italic << 1
  uint32_t fg = 0, bg = 0;    // 解析后的前景、背景（含 INVERSE、搜索高亮、选区、DECSCNM）
  bool visible = true;        // 闪烁隐藏相位、SGR 8 隐藏时为 false
};
struct ColRange { uint16_t col0, ncols; };
struct TextSpan { uint32_t begin, length; };   // 段文本中的 UTF-16 区间
struct TextRun {
  ColRange cols;
  uint8_t format = 0; uint32_t fg = 0;
  std::u16string text;
  std::vector<uint16_t> colOfUnit;   // text 每个 UTF-16 单元所在的列（绝对列）
  // 段内核心格（不含尾格）按顺序编号 0..n-1，称为「格序号」。下面两个数组都按格序号索引。
  std::vector<TextSpan> cellSpans;   // 每个核心格在 text 中的区间
  std::vector<uint16_t> cellCols;    // 每个核心格的首列（绝对列）
};
std::vector<TextRun> segmentRow(const std::vector<TextCellIn>&, std::optional<ColRange> isolate);
```

规则：

- **`format`、`fg` 或 `bg` 变化就断开。** 一段只用一个字体格式、一把画刷；背景变化处（选区、搜索高亮的边缘）也断开，这样裁剪边界（§5.4）与背景边界一致。
- `visible == false` 的格不进任何段。
- 只含空格的段丢弃（背景另画）。段内的空格保留，它们决定后续字符的位置，也是连字的上下文。
- **连字开关不影响分段**（决定）。关闭连字只改塑形特性（§4.3）。
- `isolate`：块光标所在的列范围（§7），这个范围单独成段，前后照常分段。

### 4.2 script 与方向（决定）

`MapCharacters` 只解决字体回退，不做 script 分析。每段塑形前：

1. `IDWriteTextAnalyzer::AnalyzeScript`，得到若干 script 区间（`DWRITE_SCRIPT_ANALYSIS`）。
2. `IDWriteTextAnalyzer::AnalyzeBidi`，只取每个单元的解析层级，标出 RTL 格（见下面「方向」）。
3. `IDWriteFontFallback::MapCharacters`，得到若干字体区间（字体面 + scale）。
4. `planItems`（§5.0，纯函数）：按核心字素统一字体，与 script 区间求交，在 RTL 格边界切开，再检查每个核心格是否完整落在一个项里，落不进的格降级。输出**塑形项**（shaping item：一个文本区间、一个 script、一个字体面、一个字号，是 `GetGlyphs` 的调用单位）和降级格。

区间求交、RTL 格判定、`planItems` 都是纯函数（`intersectRanges`、`rtlCells`、`planItems`），可单测。分析源和接收器（`IDWriteTextAnalysisSource` / `Sink`）是 Win32 胶水。语言区域固定 `en-us`（与现在的 TextFormat 相同），数字替换为空。

**方向**：不做 bidi **重排**。所有项 `isRightToLeft = FALSE`，绘制时 `bidiLevel = 0`。

方向只用来判断哪些格要降级，判定来源是 `IDWriteTextAnalyzer::AnalyzeBidi`（决定）：

- 段落方向固定为从左到右，对整段文本做一次 `AnalyzeBidi`，只读取每个 UTF-16 单元的**解析层级**（resolved level），**不按层级重排**。`DWRITE_SCRIPT_PROPERTIES` 没有方向字段，不用它判断。
- 一个核心格里只要有一个单元的解析层级是奇数（从右到左），这个格就是 **RTL 格**。
- RTL 格**逐格塑形**：每个 RTL 格单独成一个塑形项。效果是孤立字形、从左到右排列，与现在逐格 `DrawTextW` 相同，不出现连写形式（init / medi / fina）。这是首版的降级，不是正确的阿拉伯文、希伯来文显示；正确显示需要终端层面的 bidi 方案（F 系列，不在本设计里）。
- 方向控制字符（LRM、RLM、ALM，LRE / RLE / LRO / RLO / PDF，LRI / RLI / FSI / PDI）照常参与 `AnalyzeBidi`，所以 RLE、RLO 之后的拉丁字母也可能被判成 RTL 格。后果只是这些格逐格塑形（与旧路径相同），不会错位，记为已知行为。
- **`DWRITE_SCRIPT_SHAPES_NO_VISUAL`** 表示不可见的格式和控制字符（零宽连接符、方向控制符等），与方向无关：照常放在塑形项里交给 `GetGlyphs`，由 DirectWrite 生成不可见字形，保持不可见。它的格（如果核心把它存成独立的格）宽度照常计入定位单元。
- **从左到右的复杂 script**（天城文、泰文等）：正常塑形。塑形簇可能跨多个核心格，也可能一个核心格拆成多个簇。定位按 §5 的「定位单元」处理，放不下的单元缩放。显示效果可能与现在不同（现在是逐格孤立显示）：可能更接近正确的写法，也可能因缩放变小。手测对比（§10 第 6 项），不承诺「不会更差」。

### 4.3 塑形

每个塑形项：`GetGlyphs` + `GetGlyphPlacements`（`isSideways = FALSE`、`isRightToLeft = FALSE`、字号见 §3）。

- **特性**：连字关时传 `liga=0`、`calt=0`、`clig=0`（OpenType 默认开着的可选连字，等宽编程字体的连字都在这里）；开时不传，用字体默认。`dlig` 默认就是关的，两种情况都不传。复杂 script 必需的特性（`ccmp`、`locl`、`rlig`、`init` 等）不受影响，所以连字关时仍可能出现跨字素的塑形（天城文的连体）。这是 script 本身的要求，不是可选连字。
- **缓冲区**：初始 `maxGlyphCount = 3 × len / 2 + 16`（微软文档的建议）。返回 `E_NOT_SUFFICIENT_BUFFER` 时加倍重试，最多 3 次（上限 `8 × len + 64`）。仍失败或返回其他错误时，这一段的绘制计划标为「整段旧方式」：逐格 `DrawTextW`。在本窗口期的 `render.stats` 里计数，不逐次刷日志。光标覆盖层沿用这份计划（§7），不再重试。

## 5. 定位（纯函数）

### 5.0 一个核心字素只在一个塑形项里（决定）

**不变量**：每个不降级的核心格，它的 UTF-16 区间完整落在**一个**塑形项里。所以同一个字素的基字符和组合符总在同一次 `GetGlyphs` / `GetGlyphPlacements` 里塑形和定位，组合符的附着由字体自己完成。

为什么要专门保证：`GetGlyphPlacements` 只接受一个字体面、一个 script。字素被拆进两个项时，后一个项里没有基字形，组合符没有附着锚点，有些字体还会给孤立组合符画虚线圈。拆分有两种来源：

- **字体**：回退把基字符和组合符分给两个字体。
- **script**：核心的 `Screen::join_cluster` 按 combining 属性把字符并进前一格，不看 script；`AnalyzeScript` 可能在格内部切开 script（跨 script 的组合序列，或格式字符被分到别的区间）。

```cpp
struct ItemRange { TextSpan span; uint16_t script; uint16_t font; };   // font：字体区间下标
struct ItemPlan  { std::vector<ItemRange> items; std::vector<uint16_t> legacyCells; };  // legacyCells：格序号，升序
// cells：TextRun::cellSpans；rtl：每个格序号是否为 RTL 格（§4.2）；
// hasAll(f, k)：字体 f 是否含第 k 格的全部码点（零宽格式字符不计）。
ItemPlan planItems(const std::vector<TextSpan>& cells, const std::vector<ScriptRange>& scripts,
                   const std::vector<FontRange>& fonts, const std::vector<bool>& rtl,
                   const std::function<bool(uint16_t font, uint16_t cell)>& hasAll);
```

步骤：

1. **按格统一字体**：格只在一个字体区间里，不动；跨多个字体区间时，按区间顺序找第一个 `hasAll` 为真的字体，把整个格改成它；都不行，这个格降级。
2. **求交与切分**：script 区间与（统一后的）字体区间求交；在每个 RTL 格的两端切开，使每个 RTL 格自成一项。
3. **对齐检查**：任何一个项边界落在某个格的内部（不在格的起点或终点），这个格降级。字体在第 1 步已经统一，这里剩下的只会是 script 边界。**不做 script 合并**（决定）：哪个 script 的塑形规则适用于跨 script 的组合序列没有通用答案，猜错比降级更糟。
4. **移除降级格**：降级格的区间从所有项里挖掉（项可能因此一分为二），空项丢弃。

降级格按旧方式逐格 `DrawTextW`，与现在完全相同，计入 `render.stats`。经过这四步，不变量对所有剩下的格成立，§5.2 的累加只发生在不同的格之间。

### 5.1 定位单元

核心字素格和塑形簇是**多对多**的：一个连字簇横跨多格；一个核心格也可能在同一个塑形项里被分成多个簇（例如字体没有为基字符和组合符生成合并的簇）。由于 §5.0 的不变量，一个格不会分到两个塑形项里。定位不按簇，而按**定位单元**：

- 把每个塑形簇看成连接它所含字符所在列的一条边，列之间的连通分量就是一个定位单元。宽字符的两列天然属于同一单元。
- 单元的格范围 = 它所含列的并集（必然连续）；单元宽度 = `格数 × cellWPx`。
- 单元的**自然宽度** = 单元内所有字形自然 advance 之和。
- **单元不跨塑形项**：簇只在一次 `GetGlyphs` 内产生，只连接同一项里的格；每个格只属于一个项（§5.0）。所以一个单元的全部字形都在同一个项里。

### 5.2 绝对位置

所有字形按逻辑顺序算**绝对笔位**（相对行首的像素）：

- 单元内第一个字形的笔位 = 单元首列的左边缘。
- 单元内后续字形 = 前一个字形的笔位 + 它的自然 advance。组合符的附着已经由该项的 `GetGlyphPlacements` 完成，这里的累加不承担附着。
- 单元之间互不影响：下一个单元从它自己的首列左边缘开始。advance 不参与列计算，回退字体、比例字形、零宽组合符都不会挪动后面的格。
- offset（`GetGlyphPlacements` 的 `advanceOffset` / `ascenderOffset`）原样保留。

### 5.3 超宽单元

单元的自然宽度超出单元宽度，并且超出量 ≥ `kGlyphFitTolerancePx`：这个单元按 `fit_glyph` 缩放，即水平缩放 `s = 单元宽度 / 自然宽度`，以单元左边缘为原点，再居中。缩放的是整个单元的全部字形。

### 5.4 绘制片段与裁剪

定位的输出是一组**绘制片段**，每个片段对应一次 `DrawGlyphRun`：

```cpp
struct DrawPiece {
  enum Kind { Glyphs, LegacyCell } kind = Glyphs;
  // Glyphs
  uint16_t item;                     // 塑形项下标
  uint32_t glyphBegin, glyphEnd;     // 该项中的字形范围 [begin, end)
  float originXPx;                   // 第一个字形的绝对笔位
  std::vector<float> advancesPx;     // advances[i] = 笔位[i+1] − 笔位[i]；最后一个取自然 advance
  float scale = 1.f;                 // ≠1 时为超宽单元（§5.3）
  // LegacyCell
  uint16_t cell;                     // 格序号；文字取 run.text 的 cellSpans[cell]
  // 两种都有
  ColRange clip;                     // 裁剪的列范围；LegacyCell 为 {cellCols[cell], 本次该列的宽度}
};
struct ShapedRunView { const std::vector<ShapedItem>& items; const std::vector<uint16_t>& legacyCells; };
std::vector<DrawPiece> placeOnGrid(const ShapedRunView&, const TextRun&,
                                   const std::vector<uint8_t>& widthOfCol, float cellWPx);
```

- **降级格的数据流**：`planItems` 产出的 `legacyCells` 是格序号，随塑形结果进缓存（§8），由 `ShapedRunView` 显式传给 `placeOnGrid`，不从字形的缺口推断。片段的文字、列和裁剪都在本次定位时用**本次**的 `TextRun`（`cellSpans`、`cellCols`）和 `widthOfCol` 算出，所以同一缓存条目挪到别的列、或前面多了宽字符，降级格仍落在正确的列。
- **每格只画一次**：降级格的区间已从所有项里挖掉（§5.0 第 4 步），不会再出现在 `Glyphs` 片段里。片段按列排序输出。

- 一个项里，非超宽单元的连续字形合成一个片段，裁剪范围 = 所在段的列范围。超宽单元单独成片段，裁剪范围 = 该单元的列范围，带变换矩阵绘制。被拆出的字形**不出现在**普通片段里：普通片段在超宽单元处断开，前后各一个片段，各自用绝对笔位作原点，所以后面的字形不会移位。
- **裁剪（决定）**：普通片段裁剪到**段**的列范围 × 行高，不裁到每格。允许的差异：同一段内（同色、同背景、同样式），斜体外伸、负 side bearing、组合符的墨迹可以越过格边界；在段边界处（颜色、背景、样式变化，隐藏格，光标隔离格）被裁掉。现在逐格裁剪会把这些墨迹截掉，新路径在段内保留，更接近其他终端。§10 第 1 项按这条允许差异验收。

## 6. 彩色字形（决定）

- **支持范围**：COLR v0 分层字形，经 `IDWriteFactory2::TranslateColorGlyphRun`（Windows 8.1+）。Windows 10 / 11 自带的 Segoe UI Emoji 是 COLR v0。
- **不支持**：SVG、位图（sbix / CBDT / PNG）和 COLRv1。这些字体 `TranslateColorGlyphRun` 返回 `DWRITE_E_NOCOLOR`，按普通字形单色绘制；字体里没有轮廓时可能画不出来，记为已知限制。需要 `IDWriteFactory4` 以上的格式选择，留给以后。
- **颜色**：每层的 `paletteIndex == 0xFFFF` 表示用当前文本颜色，即段的 `fg` 画刷（块光标反色时为反色后的颜色）；其他层用字体给的固定颜色，不受 DIM、INVERSE、选区、搜索高亮影响。
- **光标反色**：光标格里的固定色层保持原色，只有 0xFFFF 层随反色变化，与其他终端一致。

## 7. 块光标与脏行（决定）

块光标要在光标格画反色字形。如果这个格被连进前后的连字，反色只会盖住半个连字，所以块光标所在的格单独成段（§4.1 的 `isolate`）。

- **隔离条件**：光标可见（DECTCEM）、形状为块（DECSCUSR 0 / 1 / 2）、IME 预编辑未进行。**与闪烁相位和焦点无关**：否则每次闪烁都要重新塑形整行，连字会随闪烁变形。失焦时块光标是空心框、不反色，但仍隔离，这样焦点变化不会引起重排。
- **隔离范围**：光标列先吸附到宽字符首格（现有 `cursor_cell`），范围是该字符的全部列。
- **与连字开关无关**：连字关时，复杂 script 仍可能跨格塑形（§4.3），隔离同样需要。
- **脏行**：渲染器记住上一帧的隔离状态（行、列范围，或无）。隔离状态变化时（光标移动、DECTCEM、形状切换、预编辑开始或结束），把**旧行和新行**都标脏，重画文本。只有覆盖层变化（闪烁、焦点）不标脏。纯函数：

  ```cpp
  struct IsolateState { std::optional<uint16_t> row; ColRange cols; };
  std::vector<uint16_t> isolateDirtyRows(const IsolateState& prev, const IsolateState& next);
  ```

- **反色字形用同一份计划（决定）**：画隔离段时，渲染器把这一段的**绘制计划**保存下来：塑形结果的共享引用（§8）、`placeOnGrid` 的片段、降级标记（§4.3 整段旧方式、§5.0 旧方式格）。覆盖层画反色字形时直接用这份计划，只把画刷换成反色颜色（彩色层按 §6），**不查缓存、不重新塑形、不重试**。底层走了旧方式，覆盖层也走旧方式；底层用了某个字体和缩放，覆盖层完全相同。塑形错误只在底层计数一次。
  - 计划随隔离状态保存：`{IsolateState, 行内容 revision, 计划}`。隔离状态或该行内容变了，这一行必然被重画（§7 脏行、内容脏行），计划随之更新；字体、DPI、连字开关变化或设备丢失时作废。只有覆盖层变化的帧（闪烁、焦点）复用上一份计划。
  - 万一计划缺失（不应发生，例如计划作废后本帧没有重画该行），覆盖层退回旧方式 `DrawTextW` 画反色字形，并计数。

## 8. 缓存（纯数据结构）

```cpp
struct ShapeKey {
  std::u16string text; uint8_t format; bool ligatures;
  std::vector<uint8_t> cellLengths;   // 每个核心格（不含尾格）的 UTF-16 长度，按顺序；与列号无关
};
struct ShapedItem {                    // 与列坐标无关
  uint32_t textBegin, textLength;      // 在段文本中的范围
  FontHandle face; float emPx;         // face 由平台层持有（不透明句柄 + 删除器）
  ScriptAnalysis script;               // {uint16_t script; uint8_t shapes;}，与 DWRITE_SCRIPT_ANALYSIS 一一对应，平台层转换
  bool rtlFallback;                    // §4.2 逐格塑形的项
  std::vector<uint16_t> glyphIndices;
  std::vector<float> advancesPx, offsetXPx, offsetYPx;
  std::vector<uint16_t> clusterMap;    // 项内每个 UTF-16 单元 → 首个字形下标
};
struct ShapedRun {
  std::vector<ShapedItem> items;
  std::vector<uint16_t> legacyCells;   // §5.0 的降级格，**格序号**（段内核心格编号，不含尾格），升序
};
class ShapeCache {                     // LRU，按字节计；默认预算 4 MiB
 public:
  std::shared_ptr<const ShapedRun> find(const ShapeKey&);  // 共享所有权：被淘汰后持有者仍可用
  void put(ShapeKey, std::shared_ptr<const ShapedRun>);
  void clear();
  Stats stats() const;                 // hits、misses、evictions、bypassed
};
```

- **键**：段文本、格式、连字开关、**核心格分组**（每格 UTF-16 长度的序列）。值里所有位置都是段内相对的：`textBegin` / `textLength` 是段文本中的 UTF-16 偏移，`legacyCells` 是格序号。键已含格分组，所以命中时这两种位置对本次输入同样有效；列号和格宽都不进缓存，每次由 `placeOnGrid` 从本次输入算出。塑形项的边界取决于格分组：RTL 格逐格塑形（§4.2），字体统一按格进行（§5.0）。同样的 UTF-16 文本可能有不同的格分组（核心把组合符并进前一格或单独成格），所以分组必须进键。键不含颜色、背景和绝对列号：同一段文字换了颜色或挪了位置也能命中。字体族、字号、DPI 变化时整表清空。
- **只缓存塑形，不缓存定位**：`placeOnGrid` 依赖每列宽度和格宽，开销小，每次重算。
- **计费**：一项的字节数 = 键文本 × 2 + 格数 + Σ 项（文本单元 × 2 + 字形数 × 14 + 64）。单项超过预算的 1/4（1 MiB）时不进缓存（`bypassed` 计数），直接用完丢弃。
- **所有权**：值是 `shared_ptr<const ShapedRun>`。缓存淘汰只放掉缓存自己的引用；本帧的绘制和 §7 保存的光标计划仍持有引用，可以安全使用。
- **句柄**：`IDWriteFontFace*` 的 AddRef / Release 放进 `FontHandle` 的删除器，随最后一个 `ShapedRun` 引用释放。纯头文件只看到不透明句柄，测试用计数删除器验证。
- **清空时机**：`setFont`、DPI 变化、连字开关变化、设备丢失。
- **旧路径的 `I.advance[4]` 保留不动**（属于旧路径，见 §9）。

## 9. 旧路径与性能度量

**旧路径（决定）**：环境变量 `ITERM2WIN_TEXT_PATH=drawtext` 切回逐格 `DrawTextW`，代码**原样保留**（包括 `I.advance` 量宽缓存），不为新路径做任何改动，这样它就是当前实现的公平基线。保留一个版本，确认无回归后删除。

**度量**：两条路径都记，每个窗口期往 `pane-diag.log` 写一条 `render.stats`。

- **测的是什么**：一帧里**文本工作**的 CPU 时间之和。渲染循环里背景、文本、装饰按行交错，所以不是从头到尾一段计时，而是在每段文本工作前后各取一次 QPC，累加成这一帧的样本（`TextTimer::begin()` / `end()`，时钟可注入）。
  - **计入**：格到文本的转换（`MultiByteToWideChar` 或 `TextCellIn` 构建）、分段、`AnalyzeScript` / `AnalyzeBidi` / `MapCharacters`、缓存查找、`GetGlyphs` / `GetGlyphPlacements`、定位、`DrawGlyphRun` 与彩色层提交、降级格的 `DrawTextW`。旧路径计入同样的内容：转换、advance 查表或量宽、`DrawTextW`。
  - **不计入**：背景矩形、下划线 / 删除线 / 上划线矩形、光标与覆盖层、`EndDraw`、`Present`。
  - 两条路径同一口径。插桩只加计时调用，不改旧路径的布局、量宽缓存和绘制顺序。
  - 这是 CPU 提交成本，不是 GPU 完成时间，也不是端到端延迟。GPU 和端到端用 PresentMon 另测（可选，§10 第 7 项）。
- **分类**：按本帧**重画的行数**（不管行里有没有字形）分三类：无文本重画（0 行，只有覆盖层）、部分（1 到 rows−1 行）、全屏（全部可见行）。空白行重画了也算重画，所以清屏后的全屏重画仍归「全屏」。三类分别统计 p50 / p95 / 最大值和样本数；无文本重画的帧只计数。
- **窗口**：10 秒或 1000 个样本，先到者为准；写一条后清零。
- **冷 / 热**：`setFont`、DPI 变化、连字开关变化、设备丢失之后的第一个窗口标 `cold=1`。
- **缓存命中率**：分母是本窗口内新路径的塑形项查找次数（按段计，`hits + misses`，`bypassed` 单列）。
- **每条记录的上下文**：路径（glyphrun / drawtext）、连字开关、DPI 缩放、网格列 × 行、重画总行数、退回旧路径的段数（§4.3）。

**验收**（手测清单 P3 新增）：同一台机器、全屏、默认字号，两条路径各跑一遍：`cat` 一个 50 MB 的混合文本（ASCII + 中文）；`vim` 整屏翻页 100 次；`htop` 一分钟。比较热窗口中「全屏」类的 p95：新路径不高于旧路径，并且 ≤ 8 ms。8 ms 只约束上面定义的文本 CPU 提交时间。达不到时先看命中率和退回次数，再考虑图集（§2）。

这些数字也给 E1（UI 线程模型 ADR）用。

## 10. 测试

可移植（macOS / Linux ctest，`tests/renderer/test_text_runs.cpp`）：

- `segmentRow`：样式、前景、背景、不可见格断段；全空格段丢弃；尾格并入宽字符；`colOfUnit` 与列一一对应（代理对、组合字符、ZWJ emoji、国旗）；`isolate` 单独成段且不影响前后；`isolate` 落在宽字符上时覆盖两列。
- `intersectRanges`：script 区间与字体区间求交；边界重合、包含、交错；空输入。
- RTL 格判定（输入是构造的解析层级）：奇数层级的单元使所在格成为 RTL 格；偶数层级（含数字在阿拉伯文中的层级 2）不是；RLE 之后的拉丁格按层级判定。
- `planItems`：格在一个字体里不动；跨两个字体时改用第一个含全部码点的字体；都不含时降级；零宽格式字符不影响 `hasAll`。**一个核心格横跨两个 script 区间、字体相同**：该格降级，不会拆成两个项；降级格从项中挖掉后项一分为二；RTL 格自成一项；输出的每个项边界都在格边界上（对所有输入断言这条不变量）。
- `placeOnGrid`（输入是构造的塑形结果，不依赖 DirectWrite）：
  - ASCII 一字一形，各落在自己的列；
  - 宽字符占两格，下一个字落在 col+2；
  - 组合字符：基字符和组合符同簇；**同一核心格在同一项内的两个簇**，组合符落在基字符之后的自然位置，下一格不受影响；
  - 降级格：`LegacyCell` 片段的列、宽度、裁剪和文字都来自本次输入；**同一缓存条目在不同绝对列复用**；**降级格前面有宽字符尾格**；**相同文本与分组、但格宽布局变化**（例如核心把某格改成宽字符）。所有情况下降级格和正常字形都落在正确的列，每格只出现在一个片段里；纯函数只验证几何不串格，组合符是否真正盖在基字符上由 Windows 图像验证（§10 第 4 项）；
  - 连字：3 字符 → 1 字形横跨 3 列；`calt` 一字一形的替代字形；
  - 比例回退字形（advance ≠ 格宽）不挪后续字形；零 advance 字形；
  - 超宽单元：缩放片段与前后普通片段的原点正确，被拆出的字形不出现在普通片段里；超出不足 1 像素的不缩；
  - 逐格塑形的 RTL 项；
  - 以上在 `cellWPx` 取 100% / 125% / 150% / 200% 对应值时都成立（含非整数 advance）。
- `isolateDirtyRows`：同一行内移动、跨行移动、出现与消失、形状变化；内容不变只动光标时旧行和新行都标脏；仅闪烁、仅焦点变化不标脏。
- `ShapeCache`：命中与未命中、LRU 顺序、字节计费与淘汰、单项过大绕过、`clear`、删除器调用次数；淘汰后仍被持有的值可用，最后一个引用释放时删除器才调用；**相同文本、不同格分组不命中**，同样文本和分组换了绝对列仍命中。
- 光标计划：塑形失败注入一次（可注入的塑形函数），底层标为整段旧方式，覆盖层用同一计划、不重试，错误只计一次；计划作废后覆盖层走旧方式并计数。
- `TextTimer` 与 `render.stats`（可注入时钟）：背景、文本、装饰交错时只有文本区间进样本；分类按重画行数，含空白行的全屏重画归「全屏」；分位数、窗口按 10 秒或 1000 样本重置、冷热标记。
- 现有 `fit_glyph` 用例保留。
