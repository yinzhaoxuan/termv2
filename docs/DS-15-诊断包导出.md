# DS-15 诊断包导出与脱敏（D8）

日期：2026-11-04
基线：main `0b72f82`
出处：`REVIEW.md` GAP-13（「诊断包预览和脱敏导出」）、§8 D8；增补 10-31 DS-11；REVIEW §8 C6（实机结果要绑定提交号与 Windows 版本）；`docs/ssh-direct.md`「日志可能含主机名、主机密钥指纹和 agent 管道路径，导出前需自行脱敏」。

凡写「决定」的地方，是本文替原设计补的选择。

## 0. 现状

- 窗格诊断写入 `<configDir>/logs/pane-diag.log`，5 MiB × 3 滚动（`.1`、`.2`），每行 `v=1 sid= attempt= phase= elapsed_ms= err= bytes= msg=`（`formatPaneDiagLine`）。不含终端原始输出。shell 没给后端传 `configDir`，后端用 `%APPDATA%\it2w`，与 shell 默认 `configDir` 相同。
- `msg` 可能含：主机名 / IP（Direct 阶段、会话结束的错误文字）、`user@host`、主机密钥类型与 `SHA256:` 指纹（`ssh.direct.hostkey`）、`hv-<VM GUID>` 与 VM GUID、agent 管道路径（`ssh.direct.agent`）、本地程序与工作目录路径（启动失败文字，常含 `C:\Users\<名字>`）。
- 没有导出入口；用户要手动找文件、手动脱敏。没有任何地方记录产品构建对应的提交号。

## 1. 目标与边界

做：

1. 系统菜单「导出诊断包…」：收集 → 脱敏 → **预览** → 用户确认后保存为一个 UTF-8 文本文件。
2. 诊断包含：构建与环境信息（提交号、Windows 版本、Direct 是否编译进来、诊断相关环境开关）、配置摘要（只有计数和开关，不含主机等明细）、三份滚动日志（旧到新）。
3. 脱敏：按配置里已知的敏感值精确替换，再按模式替换 IP、指纹、GUID、管道名、用户目录；同一个原值在整个包里替换成同一个记号（如 `<host-1>`），便于对照。
4. CMake 在配置时把 `git rev-parse --short HEAD` 写进 `it2w_shell`，诊断包和（以后的）关于框都用它。

不做：

- 不做 zip（Windows 没有简单的系统 API；单个文本文件已经够用，也方便贴到 issue）。
- 不收集 `connections.json`、`settings.json`、`known_hosts` 原文，不收集崩溃转储、性能计数。
- 不保证脱敏完备：预览就是为了让用户最后把关。界面上明确写「请检查后再发送」。
- 不改日志本身的格式和写法（落盘仍是明文，只在导出时脱敏）。

## 2. 诊断包格式（决定）

文件名默认 `it2w-diag-YYYYMMDD-HHMMSS.txt`（本地时间）。内容：

```
# it2w 诊断包
# 已脱敏：主机、用户、IP、指纹、GUID、管道名与用户目录已替换为 <类别-序号>。发送前请检查。

[构建与环境]
生成时间 = 2026-11-04 21:03:11 +08:00
提交（配置时） = 0b72f82
构建 = Release / MinGW / Direct 已编译
Windows = 10.0.22631
ITERM2WIN_SSH_DIRECT = 1
ITERM2WIN_OSC52_PING = (未设置)

[配置摘要]
connections.json = 已读取，revision 7，12 个连接（SSH 手动 8 / Hyper-V 2 / 本地 2），校验未通过 1 个
传输 = 跟随默认 9 / 兼容 1 / 直连 2
settings.json = 已读取；字体 Cascadia Mono 12；osc52 = 写开 / 读关 / 0；confirmMultilinePaste = 默认
外观 Profile = 3 个（无效 0）
改过的快捷键 = copyOrInterrupt, pasteCtrlV

[日志 pane-diag.log.2]（缺失）
[日志 pane-diag.log.1]（5242880 字节）
v=1 sid=3 attempt=1 phase=ssh.direct.hostkey ... msg=ssh-ed25519 <fingerprint-1>
...
[日志 pane-diag.log]（截断：只保留最后 5242880 字节，从下一整行开始）
...
```

- 节标题与键名是中文、固定；值由 §3 / §4 的纯函数生成。
- 每份日志最多读最后 `kDiagLogTailBytes`（5 MiB，与滚动上限相同）。超出时从截断点后的第一个换行开始，并在节标题里注明。文件不存在写「（缺失）」，读失败写「（读取失败：原因）」。
- 日志里的 `\r\n` 统一成 `\n`；不改其他字节。非 UTF-8 字节原样保留（日志本来就是 UTF-8）。

## 3. 收集（`uicfg`，新文件 `ui/include/uicfg/diag_bundle.h`、`ui/src/diag_bundle.cpp`）

```cpp
struct DiagEnvironment {                 // main.cpp 填写；纯数据
  std::string generatedAt, commit, build, windowsVersion;
  std::vector<std::pair<std::string, std::string>> envFlags;   // (名字, 值或 "(未设置)")
};
// 配置摘要：只出计数与开关（§2 示例）。connsStatus / settingsStatus 是加载结果（LoadStatus）。
std::vector<std::string> configSummaryLines(const ConnectionsFile&, LoadStatus connsStatus, const FileValidation&,
                                            const SettingsFile&, LoadStatus settingsStatus);

struct DiagLogSection { std::string name; std::optional<std::string> text; std::string note; };  // text 空 = 缺失或失败
inline constexpr std::size_t kDiagLogTailBytes = 5u << 20;
// 按 .2、.1、当前文件的顺序读取；每份最多 maxBytes（截断规则见 §2）。
std::vector<DiagLogSection> readDiagLogs(const std::filesystem::path& logsDir, std::size_t maxBytes = kDiagLogTailBytes);

// 拼出 §2 的完整文本，然后整体过一遍 redactDiagnosticText（§4）。
std::string buildDiagnosticBundle(const DiagEnvironment&, const std::vector<std::string>& summary,
                                  const std::vector<DiagLogSection>&, const RedactionContext&);
// it2w-diag-YYYYMMDD-HHMMSS.txt；参数是已经格式化好的本地时间戳 "YYYYMMDD-HHMMSS"
std::string diagnosticFileName(const std::string& stamp);
```

调用方：`FileValidation` 在导出时用 `validateConnectionsFile(g->conns)` 现算（编辑器保存后会变）；两个 `LoadStatus` 由 `App` 在启动时记下（新增 `connsLoadStatus`、`settingsLoadStatus`）。

`configSummaryLines` 不输出任何主机、用户、路径、VM ID、Profile ID、字体以外的自由文本。字体族名会输出（不敏感，排查渲染问题需要）。

## 4. 脱敏（同一文件）

```cpp
struct RedactionContext {
  // 精确替换的已知值。类别决定记号前缀：host / user / vm / path。
  std::vector<std::pair<std::string, std::string>> known;   // (类别, 原值)
};
// 从配置与环境收集已知值：
//   host：manual 主机、Hyper-V 回退地址；user：SSH 用户名、Windows 用户名；vm：VM ID（规范化前后两种写法）；
//   path：密钥文件、本地程序、工作目录、用户主目录、configDir。
RedactionContext redactionContextFrom(const ConnectionsFile&, const std::vector<std::pair<std::string, std::string>>& extra);
std::string redactDiagnosticText(std::string_view text, const RedactionContext&);
```

规则，按顺序执行：

1. **已知值**（`known`）：按原值长度从长到短替换，这样路径先于其中的用户名被替换。
   - 主机与用户名不区分 ASCII 大小写；路径不区分大小写，且把 `/` 与 `\` 视为相同。
   - **边界**：匹配处前后的字符都不能是 `[A-Za-z0-9_]`（路径值不检查边界）。避免用户名 `root` 把 `rootfs` 里的一段也替换掉。
   - 长度小于 3 的值不做精确替换（太容易误伤）；它们仍可能被后面的模式规则覆盖。设计文档与预览说明里写明这一点。
2. **模式**：
   - `SHA256:` 后接 43 个 base64 字符（可带尾部 `=`）→ `<fingerprint-N>`。
   - GUID（8-4-4-4-12 十六进制，可带花括号；含 `hv-` 前缀时连前缀一起）→ `<guid-N>`。
   - IPv4 点分四段（每段 0–255，前后不是数字或点）→ `<ipv4-N>`。`127.0.0.1` 与 `0.0.0.0` 保留原样。
   - IPv6：含至少两个 `:`、由十六进制组与 `::` 组成、可带 `%scope`、可带 `[]` 的片段 → `<ipv6-N>`。`::1` 保留原样。实现时注意不要把 `elapsed_ms=12:34` 这类时间、`HH:MM:SS` 误判（要求至少一个组含 a–f，或出现 `::`，或组数 ≥ 4）。
   - `\\.\pipe\` 管道名：`openssh-ssh-agent` 保留；其他 → `\\.\pipe\<pipe-N>`。
   - `X:\Users\<名字>\`（大小写不敏感，`/` 也算）→ `X:\Users\<user-home>\`；名字为 `Public`、`Default` 时保留。
3. **记号稳定**：同一类别里，同一个原值（主机、用户按小写比较）在整个包里得到同一个序号，序号按第一次出现的位置从 1 起。
4. 只替换 `msg` 等自由文本吗？**决定：整个包都过一遍**（包括节标题和摘要），实现简单、也不会漏；§3 的摘要本来就不含敏感值，过一遍无害。

## 5. 界面（`main.cpp` + 资源，薄胶水）

- 系统菜单在「恢复默认配色」后加「导出诊断包…」。
- 点击：`main.cpp` 填 `DiagEnvironment`（提交号来自编译定义 `IT2W_BUILD_COMMIT`；Windows 版本用 `RtlGetVersion`，经 `GetProcAddress(GetModuleHandleW(L"ntdll.dll"), "RtlGetVersion")` 取得；构建字段由 `NDEBUG` / `IT2W_SSH_DIRECT` 推出；环境开关读 `ITERM2WIN_SSH_DIRECT`、`ITERM2WIN_OSC52_PING`），调 `configSummaryLines`、`readDiagLogs(g->configDir / "logs")`、`redactionContextFrom(g->conns, extra)`（extra：`%USERNAME%` 为 user，`%USERPROFILE%` 与 `configDir` 为 path，`%COMPUTERNAME%` 为 host），再 `buildDiagnosticBundle`。
- **预览对话框** `IDD_DIAG_PREVIEW`（放进 DS-14 的 `.rc` 与 `resource.h`）：顶部说明「以下内容已自动脱敏（主机、用户、IP、指纹等）。少于 3 个字符的名字不会被替换。请检查后再保存或发送。」；中间只读多行编辑框（等宽字体 Consolas，`EM_SETLIMITTEXT` 设为 0 解除 32K 限制，带横竖滚动条）；底部「保存…」「取消」。对话框代码放进 `connection_dialog.cpp` 旁的新文件 `ui/shell_win32/diag_dialog.{h,cpp}`，接口 `bool runDiagPreview(HWND, HINSTANCE, const std::string& text)`（true = 用户点了保存）。
- 「保存…」→ `GetSaveFileNameW`，默认文件名 `diagnosticFileName(本地时间戳)`、默认目录「文档」、过滤器 `*.txt`、`OFN_OVERWRITEPROMPT`。写文件用 `uicfg::writeDurable` + `replaceFile`（与配置文件相同的原子写法）。成功后状态栏「已导出诊断包：<文件名>」（只显示文件名，不显示完整路径）。
- 收集阶段在 UI 线程同步做（最多读 15 MiB，几十毫秒级）；不另开线程。

## 6. 构建：提交号

根 `CMakeLists.txt`（或 `ui/CMakeLists.txt`）在配置时：

```cmake
execute_process(COMMAND git rev-parse --short HEAD WORKING_DIRECTORY ${PROJECT_SOURCE_DIR}
                OUTPUT_VARIABLE IT2W_BUILD_COMMIT OUTPUT_STRIP_TRAILING_WHITESPACE ERROR_QUIET RESULT_VARIABLE rc)
if(NOT rc EQUAL 0 OR IT2W_BUILD_COMMIT STREQUAL "") set(IT2W_BUILD_COMMIT "unknown") endif()
```

只给 `it2w_shell` 加 `IT2W_BUILD_COMMIT="..."`。它是**配置时**的提交，增量构建不会更新；诊断包里键名就叫「提交（配置时）」，避免误导。

## 7. 测试

平台无关，进 ctest（新 `ui/tests/diag_bundle_tests.cpp`，按模式拆）：

- **redact**：每条模式规则的正例与反例（`127.0.0.1` / `::1` / `openssh-ssh-agent` / `Public` 保留；`12:34:56` 不当 IPv6；`999.1.1.1` 不当 IPv4；`hv-<guid>` 整体替换）；已知值的长度优先（路径先于其中的用户名）、大小写、`/` 与 `\`、边界（`root` 不碰 `rootfs`）、长度 < 3 不替换；记号稳定（同值同号，不同值递增，主机大小写不同算同一个）。
- **readDiagLogs**：顺序 `.2 → .1 → 当前`；缺失文件；超过上限时只保留尾部并从下一整行开始；`\r\n` 归一。
- **configSummaryLines**：计数正确，输出里不出现任何测试数据中的主机、用户、VM ID、路径（逐个断言不包含）。
- **buildDiagnosticBundle**：一份含真实形状日志行（取 `ssh.direct.hostkey`、`ssh.direct.agent`、`session.end` 的典型 msg）的端到端用例，断言敏感值全部消失、记号出现、节结构完整。
- **diagnosticFileName**。

只能在 Windows 上验的（写进 STATUS「未验证」）：

1. 系统菜单导出：预览可滚动、大日志（接近 15 MiB）不卡死；保存的文件用记事本打开是 UTF-8 中文正常。
2. 用 Direct 连接一台未信任主机后导出：指纹、主机、用户都被替换；`Windows =` 是实际版本号；`提交（配置时）` 与构建一致。
3. 取消不写文件；同名文件提示覆盖。
4. CI `mingw` 编译通过。
